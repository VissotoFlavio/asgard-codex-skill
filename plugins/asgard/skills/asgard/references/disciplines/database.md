# Database discipline

Load this guidance for schema, migration, index, partition, or backfill work. Route the activity to `$regin`; its skill-local guidance is canonical for database profiles, inventories, VPS container access, and phase-specific operational controls. This root guidance grants no connection or mutation authority.

## Activity contract

Before dispatch, record engine/version, artifacts, entities, current/desired structure, compatibility, volume, sequence, and evidence in the task-local contract.

Include the affected columns/types/nullability/defaults, keys, constraints, indexes, relations, partitions, query paths, referential actions, ordering, and compatibility assumptions. Require an expand/contract approach; contract only after verified consumers/data and separate approval.

For each migration/backfill, identify transactions, locks, volume, batching, idempotency, checkpoints, resumability, partial failure, verification, reversibility, recovery, and lossy steps for the `$regin` contract.

## Dispatch and review boundary

Require `$regin` to apply its canonical `AUTHOR`/`VALIDATE`/`APPLY` authority model, target verification, least privilege, drift, partial-failure, and recovery controls. The task-local contract must state the permitted phase and its exact authority; the root guidance does not restate or grant those controls.

Select `$tyr` for material integrity or compatibility review, `$loki` for recovery behavior, and `$heimdall` for security or availability review when their independent boundary is justified. Odin selects these leaf skills; `$regin` never self-approves.
